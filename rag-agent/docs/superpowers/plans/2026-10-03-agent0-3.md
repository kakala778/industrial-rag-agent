# Agent 0.3 Bounded Evidence Reference Contract Implementation Plan

> **For agentic workers:** Execute natively in the current checkout, task by task, using TDD. Do not create a worktree or commit. Keep RAG, retrieval, BGE, chunking, MinerU, progress guards, prompts for task-specific cases, and frameworks unchanged.

**Goal:** Add an opt-in evidence-ID finding contract where the host validates selected evidence, creates bounded authentic excerpts and provenance, and accepts explicit unsupported-scope outcomes.

**Architecture:** Keep the Agent 0.2 copied-quote contract as the compatibility default. Add a contract selector mode to the same Agent harness and DeepSeek client; the reference mode returns per-scope statuses and evidence IDs, then the host validates task/session eligibility and renders citations from its current registry. Evaluation replays frozen SEARCH observations and existing cached LOOKUP blocks, comparing the Agent 0.2 DeepSeek result with one bounded DeepSeek reference-contract pass.

**Tech Stack:** Existing Python stdlib JSON/urllib/hashlib, existing unittest suite, existing cached MinerU corpus and frozen Agent evaluation inputs. No new dependency.

**Spec:** User-provided Agent 0.3 attachment, `docs/agent0-3-bounded-evidence-contract.md` acceptance questions.

## Global Constraints

- RAG, retrieval, BGE, chunking, MinerU, progress/coverage rules, and Agent framework remain unchanged.
- Never use expected answers, target fields, candidate labels, or benchmark annotations in host span generation or selector inputs.
- Keep private PDFs, queries, QA, labels, evidence text, actions, credentials, and traces under ignored `outputs/` only.
- Do not install dependencies, commit, push, merge, or start another milestone.
- Preserve the existing copied-quote contract as the default and baseline.

## Review Focus

- An ID from another task/session is rejected unless it is observed and looked up in the current task and belongs to this session.
- Unsupported statuses cannot carry evidence IDs; no-candidate status requires successful empty searches.
- Text/table excerpts remain exact parent substrings, within a fixed maximum, with honest fallback when offsets/rows are ambiguous.
- Citation provenance comes only from the active registry; model claims never become source text.
- Finish traces include IDs, per-scope status, span metadata, provenance, and terminal status without hidden reasoning or duplicate evidence text.
